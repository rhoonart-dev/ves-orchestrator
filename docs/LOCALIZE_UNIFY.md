### 0-1. 🛑 결정 번복 — 영상 선택은 다시 자동이다 (2026-08-25)

> "영상 선택은 이전처럼 알아서 진행하게 해줘."

**결정 2("자동 선별·승인은 폐기 — 사람이 지시한다")를 번복한다.** P3b·P5-2 가 그 전제로
만들어졌으므로(선별기는 점수만, 거는 것은 사람) 그 자리들을 함께 고쳤다:

- `loopy_picker` 가 `automation='auto'` 일 때 상위부터 `per_day` 만큼 **작업지시까지** 세운다.
- 거는 일은 `_select_external_short_impl` **한 곳**이고 사람 손(RPC)도 그것을 부른다 —
  두 벌로 나뉘면 자동 경로만 가드(중복·차단·롱폼 게이트·동시성)가 빠진다.
- 사람이 손으로 건 편(`origin='manual'`)은 자동 몫을 안 잡아먹는다.

⚠ **바뀌지 않은 것: 발행은 여전히 사람이다.** 자동이 되는 것은 '오늘 무엇을 작업할지'
까지고, 그 뒤 검수함 → 승인 → publish 는 그대로다. 대시보드의 "발행은 어느 자동화
수준에서도 사람입니다" 문구도 그대로 유효하다.

## 2. 목표 상태 — 한 문장

> **ai-video 가 유일한 생성·현지화 엔진이고, ves-orchestrator 가 유일한 관제이며,
> 채널의 차이는 코드 경로가 아니라 설정(design/localize 키)으로만 표현된다.**

따르는 계(系):
- 엔진 진입점은 `python -m app.cli` 하나. 어댑터는 argv 만 만든다.
- `video-localization-project` 는 이관 완료 후 **동결**(read-only 참조·이력 보존).
  ⚠ 동결 전까지 vlp 를 계속 배포한다 — 컷오버는 플래그 뒤에서 병행한다(§9).
- 채널이 늘어도 코드는 안 늘어난다: `localize` 프로필 한 덩이를 추가할 뿐이다
  (사용자: "물론 이후에 추가될 수도 있어").

## 3. ai-video — 새 계층 `app/localize/`

### 3-1. 모듈 지도

```
app/localize/
  __init__.py      계약·모드 상수      (LocalizeSpec / LocalizeResult)
  spec.py          채널 현지화 프로필 파싱·검증 (design.localize → LocalizeSpec)
  collect.py       L0 수집·백업        (localize_backup_ko/ — 재실행해도 이중 번역 없음)
  telop.py         L2·L2b 텔롭 추출·타이밍 프레임 대조 (Gemini Pro 1장=1콜 규약)
  translate.py     L1 문맥 통번역 + 용어집 강제 + response_schema + 줄 단위 캐시
  apply.py         L3 데이터 계층 교체 (subtitle_segments·checkpoint_story·
                                        checkpoint_resources·edit_plan)
  narration.py     L3t 일본어 내레이션 재합성 (tts.py 재사용 — 3-4)
  rerender.py      L4 재렌더 + 텔롭 ASS 번인 (gen_flags 복원)
  meta.py          L5 유튜브 제목·설명·해시태그 + ko_ja_pairs
  overrides.py     편집실 오버라이드 병합 (줄 단위 ko/ja 선택 — §7)
  external/        완성본 입력 경로(잔망루피 쇼츠)
    detect.py      OCR (paddleocr → rapidocr 폴백)
    mask.py        마스크 기하
    inpaint.py     opencv | lama | sttn | propainter (상업 게이트 유지)
    dub.py         ASR → 트랜스크리에이션 → 클론 TTS → 보컬 분리 → 믹스
    overlay.py     render_mode: subtitle | replace | clean | bilingual
    cuts.py        완성본 시간축 구간 잘라내기 (E9 계약 승계)
  qa.py            역번역 자기검증 · 용어집 위반 · 언어 이탈 검사
  data/
    locales.json   로케일 렌더 자원(폰트·TTS 보이스 맵)
    works.json     작품별 표기·용어집·필수 고지  ⚠ 내부 키는 절대 번역 안 함
    persona.md · font_map.yaml · glossary.yaml
```

**원칙: 새 파일로만 들어온다.** 기존 `app/modules/*` 는 재사용만 하고 수정하지 않는다.
수정이 필요하면 그 자체로 별건 발주(E10~E14 가 세운 규약).

### 3-2. 현지화 모드 — 둘뿐이다 (용어 통일)

| 모드 | 입력 | 화면 속 한글 | 컷 재현 | 쓰는 채널 |
|---|---|---|---|---|
| **`rerender`** | ai-video job 디렉토리(체크포인트) | 애초에 안 그린다 | gen_flags 복원 → 프레임 단위 | 혜미리예채파 · 잔망루피 **롱폼** |
| **`overlay`** | 완성 mp4 한 개 (외부 소스) | 인페인팅으로 지우거나(replace) 병기(bilingual)하거나 그대로(subtitle) | 해당 없음(원본 시간축) | 잔망루피 **쇼츠** |

기존 등급 A/B/BJ/C/BC 는 **`overlay` 안의 `route`** 로 강등된다
(`rerender` 에는 등급이 없다 — 등급 J·B 를 `mode` 와 섞어 쓰던 혼선의 근원).

| route | inpaint | render_mode | dub | 뜻 |
|---|---|---|---|---|
| A | ✗ | subtitle | ✗ | 무변환 — 자막 트랙만 |
| B | ✓ | replace | ✗ | 화면 한글 지우고 일본어 재합성 |
| BJ | ✗ | bilingual | ✗ | 한글 두고 일본어 병기 |
| **C** | ✓ | replace | ✓ | **더빙 — 잔망루피 실운영 라우트** |
| BC | ✓ | clean | ✓ | 더빙 + 더빙자막이 자막 담당 |

### 3-3. CLI 계약

```bash
# ① rerender — 생성이 끝난 job 을 그 자리에서 현지화 (혜미리예채파·잔망루피 롱폼)
python -m app.cli localize --job-dir <job> --locale ja [--overrides <json>]

# ② overlay — 완성본 한 개를 현지화 (잔망루피 쇼츠)
python -m app.cli localize --video <mp4> --video-id <id> --locale ja \
       --mode overlay --route C --voice <elevenlabs_voice_id> [--overrides <json>]

# ③ 생성과 한 번에 (롱폼 → 쇼츠 → 현지화)
python -m app.cli create_shorts … --localize ja
```

- **미지정 = 종전 그대로.** `--localize` 없는 실행은 파일 한 바이트도 안 변한다
  (E11·E13 이 세운 게이트 규약 — KR 채널 20개의 회귀 0 조건).
- 허용값 밖은 argparse `choices` 로 **즉시 실패**. 조용히 기본값으로 떨어지면
  사람은 일본어판을 만든 줄 알고 한국어판을 발행한다.
- 성공 마커·산출 규약은 **지금 것을 그대로 승계** —
  `<job>/localize_ja/metadata.json`, `<job>/shorts.mp4` 교체본,
  한국어 원본은 `localize_backup_ko/`·`shorts_ko.mp4`.
  ⇒ 어댑터·검수함·편집실이 컷오버 순간에 안 깨진다.

### 3-4. 이관하면서 합치는 것 (중복 제거)

### 3-5. 채널 현지화 프로필 (design 키 확장)

오케스트레이터 `channel_design_overrides`(0014) 에 `localize` 한 덩이를 추가한다.
어댑터는 이 값을 그대로 CLI 플래그로 옮긴다 — 판단은 하지 않는다.

```json
"localize": {
  "locale": "ja",
  "mode": "overlay",               // rerender | overlay
  "route": "C",                    // overlay 전용
  "work": "잔망루피 유튜브 숏폼",    // works.json 조회 키 — ⚠ 내부 키, 절대 번역 안 함
  "voice": "elevenlabs:<voice_id>",
  "narration": "ja",               // ja | keep — 내레이션 TTS 를 일본어로 재합성할지
  "audio": "dub",                  // keep | dub — 원본 대사 오디오 처리
  "subtitle_font": "…", "title_font": "…", "telop_font": "…"
}
```

기존 `ops_config.localize_levels/backends/voices` 3종은 이 한 키로 흡수한다
(채널 설정이 세 군데 흩어져 있어 "어느 값이 이겼는지" 를 사람이 못 읽는다).

## 5. 잔망루피 (LOOPY) — 아카이브 + 두 갈래

### 5-1. 전체 그림

```
                    ┌──────────────────────────────────────┐
   유튜브            │  loopy_scout (매일 1회, 관제 스케줄러) │
   @zanmangloopy ───▶│  채널 전량 나열 → 길이로 두 선반에 분류 │
                    └────────────┬─────────────┬───────────┘
                                 │             │
                    ≤ 61초 ──────▼             ▼────── > 61초
              ┌────────────────────┐   ┌────────────────────┐
              │ 쇼츠 아카이브       │   │ 롱폼 소스           │
              │ external_shorts    │   │ sources            │
              │ 전량·영구 보관      │   │ 신규분·30일 보관     │
              └─────────┬──────────┘   └─────────┬──────────┘
                        │ 선별기(§5-6)              │ 사람이 작업카드로 지시
                        │ → 사람 승인               │
                        ▼                        ▼
          work_order(shorts_jp_overlay)   work_order(shorts_jp_localized)
                        │                        │
              acquire → localize(overlay)   acquire → generate → localize(rerender)
                        │                        │
                        └──────────┬─────────────┘
                                   ▼
                    localization_qa 검수 카드 → 편집실 → 발행(사람 공개)
```

**수집기는 하나, 선반이 둘이다.** `scout.py` 가 이미 길이를 알고 있으므로
(`parse_iso8601_duration`) 분류는 규칙 한 줄이다. 쇼츠 요청과 롱폼 요청을 같은
기계로 답한다.

### 5-2. (a) 쇼츠 현지화 — 기본 갈래

```
선별기가 오늘 몫을 고름(§5-6) → 사람 승인 → work_order(pipeline=shorts_jp_overlay)
  → acquire(yt-dlp 다운로드) → localize(mode=overlay, route=C)
  → upload_artifacts → localization_qa 검수 카드 → 편집실 → 발행
```
- ai-video 생성 파이프라인(분석·스토리·클립 선정)을 **안 탄다.** 사용자 지시대로
  "ai-video 기능은 거의 안 쓰고 이관된 기능만" 이 그대로 성립한다.
- 그럼에도 **작업지시(work_order)가 생긴다** — 이것이 홈·편집실 동등화의 열쇠다(§6-2).
- 폐기는 **발행 승인 자동화**(`auto_approve`)와 라우트 강제(`force_route`),
  그리고 낡은 실행 껍데기(`zanmang_daily`·`zanmang_autopilot` 잡·`report`)뿐이다.
  ⚠ **`scan`·`score` 는 폐기가 아니라 승격**된다 — 각각 수집기(§6-3)와 선별기(§5-6)가 된다.
  발행 이력(uploaded/url/published_at)도 반드시 이관한다 — 지우면 같은 영상을 두 번 올린다.

### 5-3. (b) 롱폼 → 쇼츠 — 확장 갈래

```
loopy_scout 롱폼 선반 → sources 등록 → 사람이 작업카드로 지시
  → 일반 채널과 완전 동일한 generate → localize(mode=rerender) → 검수 → 발행
```
- 이 갈래에서 잔망루피는 **혜미리예채파와 같은 코드 경로**를 탄다.
  화면에 한국어가 애초에 안 그려지므로 인페인팅이 불필요하고 품질도 더 낫다.
- 자동 수집은 **소스 등록까지만**이다. 무엇을 만들지는 사람이 정한다(결정 2).

### 5-4. 쇼츠 아카이브 — 무엇을 얼마나 들고 있는가 (결정 5)

**2층 구조.** 메타는 전량 영구, 파일은 필요할 때.

| 층 | 무엇 | 범위 | 언제 | 어디에 | 크기(추정) |
|---|---|---|---|---|---|
| **① 메타 카탈로그** | video_id·제목·길이·조회수·좋아요·댓글수·공개일·썸네일 URL | **전량(~1,100편) 영구** | 최초 1회 전량 백필 + 매일 증분 | PG `external_shorts` | 행당 ~1KB → **~1MB** |
| **② 원본 파일** | 실제 mp4 | 쓰기로 정한 것 + 최신 50편 미리받기 | 지정 시 `acquire`, 최신분은 야간 프리페치 | `ves-sources`(내용주소 sha256) | 편당 5~15MB |

- **전량 파일 다운로드는 하지 않는다.** 1,100편 × 10MB ≈ 11GB 를 받아도 실제로 쓰는 건
  극히 일부고, 고빈도 다운로드는 차단 위험이 있다(vlp README 가 ytdlp 백엔드를
  "ToS 그레이존 + 고빈도 시 차단 리스크" 로 명시). 대신 **최신 50편만 야간에 미리
  받아** 사람이 고르자마자 바로 돌 수 있게 한다.
- 지표(조회수·좋아요)는 **매일 갱신**한다. 아카이브가 단순 목록이 아니라 "무엇이
  일본에서 먹힐까" 를 사람이 판단하는 자료이기 때문이다. 폐기하는 것은 **자동 선별**
  이지 **선별을 돕는 신호**가 아니다.
- 상태 표시: `사용 안 함 / 준비됨(파일 있음) / 작업중 / 발행됨`. 발행분은 아카이브에서
  회색 처리되고 다시 못 고른다(중복 발행 방지 — 구 원장의 state 를 이관해 계승).

### 5-5. 수집 주기·보관 (결정 7 = 기본값)

| 항목 | 기본값 | 근거 |
|---|---|---|
| 수집 주기 | **매일 1회 03:00 KST** | API 46유닛(무료 쿼터의 0.5%)이라 매일 전량 재나열해도 무료. 생성 피크(09:00 planner)와 겹치지 않는다 |
| 최초 백필 | **전량 1회** | 사용자 요청 "옛날 것부터" |
| 쇼츠 메타 보관 | **영구** | 1MB 다 — 지울 이유가 없다 |
| 쇼츠 파일 보관 | **90일 미사용 시 정리**(발행분 제외) | `diskgc`·`storage_gc` 정책에 편입 |
| 롱폼 수집 | **신규분만** | 기본값 유지 |
| 롱폼 파일 보관 | **30일** | 편당 수 GB — 기본값 유지 |
| 백엔드 | **YouTube Data API v3 우선**, 키 없으면 yt-dlp | 정확한 지표 + 차단 위험 회피 |

### 5-6. 소재 선별기 — 무엇을 오늘 올릴 것인가 (결정 8)

아카이브가 1,100편이면 목록만으로는 못 고른다. **거르고 → 순위를 매기고 → 사람이 승인**하는
세 층을 둔다. 새로 만드는 것은 **게이트 1(문제 소지)** 뿐이고, 나머지는 이미 있는 코드다.

```
전량 아카이브 ~1,100편
      │
      ▼  게이트 0 — 제외 (자동·되돌릴 수 없음)
      │   이미 발행 · 내용 중복 · 진행 중 · 길이 범위 밖 · 원본 소실
      ▼  게이트 1 — 문제 소지 (자동 판정 + 사람이 뒤집을 수 있음)   ★ 신설
      │   차단 목록 · LLM 심사(권리·시의성·번역 가능성)
      ▼  게이트 2 — 순위 (지금 올리기에 적당한 순)
      │   jp_score 4신호 + 시의성·다양성·성과 피드백
      ▼
   오늘의 추천 N편 → 사람이 승인 → 체인 → 검수 → 발행
```

#### 게이트 0 — 제외 (hard)

여기서 걸린 것은 화면에 후보로 뜨지도 않는다.

| # | 조건 | 근거·비고 |
|---|---|---|
| 1 | `state = uploaded` | **이미 있는 장치다.** 원장의 `uploaded` 는 전이표에서 `set()` — 종착이라 되돌아가지 못한다. 주석이 "중복 업로드 방지(R10)의 단일 진실 소스"라고 못박고 있다. 이관해도 이 성질을 그대로 옮긴다 |
| 2 | **내용 중복** | ⚠ **원장이 못 막는 구멍.** 원장은 `video_id` 로만 판정한다 — 원 채널이 같은 내용을 **새 id 로 재업로드**하면(컴필레이션·리업로드, 캐릭터 채널에 흔하다) 그대로 통과한다. §5-7 참조 |
| 3 | `state ∈ (processing, pending_approval, approved)` | 진행 중인 편 |
| 4 | 길이 `< 8초` 또는 `> 61초` | 쇼츠 규격 밖 |
| 5 | 원본 비공개·삭제 | 수집 후 사라진 편(수집 때 감지해 표시) |

#### 게이트 1 — 문제 소지 (신설)

**세 겹이고, 신뢰도 순서대로 이긴다.**

**(a) 차단 목록** — 사람이 관리하는 확정 규칙(`ops_config.loopy_denylist`).
제목·설명 키워드, 특정 시리즈, 기간. 가장 신뢰도가 높고 감사 가능하다.
**사람이 막은 것은 LLM 이 못 푼다.**

**(b) LLM 심사** — 제목·설명·태그·썸네일을 Gemini 에 넣어 위험 플래그를 뽑는다.
`jp_score.llm_score_batch` 의 배치 호출을 그대로 확장한다(같은 콜에 실어 비용 0 증가).

| 플래그 | 무엇 | 기본 처분 |
|---|---|---|
| `collab` | 타 브랜드·IP 콜라보 | **차단** — 일본 재배포 권리가 원작 계약 밖일 수 있다 |
| `sponsored` | 유료 광고·PPL(유튜브 유료 프로모션 표시 포함) | **차단** — 광고주 권리는 한국 한정 |
| `music` | 특정 음원 의존(커버·챌린지) | **차단** — 음원 권리는 지역별로 따로다 |
| `event` | 종료된 이벤트·굿즈·팝업 홍보 | **차단** — 지금 올리면 거짓 정보가 된다 |
| `seasonal` | 계절·명절 소재 | **철이면 가산, 철이 아니면 차단**(±3주 창) |
| `topical` | 한국 시사·유행 밈 의존 | 경고 — 오래된 것일수록 감점 |
| `wordplay` | 한국어 말장난 의존 | 경고·감점 — 잔망루피는 `~뤂` 어미가 캐릭터 정체성이라 특히 잦다. `language_dependence`(이미 있다)와 같은 축 |

**(c) 실측 판정(precheck)** — 파일을 받은 뒤에만 가능하다.
`precheck.decide_route` 가 이미 프레임 OCR + ASR 로 번인·대사 유무를 실측한다.

> ⚠ **그래서 게이트 1 은 2단이다.** (a)(b)는 파일 없이 메타만으로 도니까 아카이브 전량에
> 매일 돌고, (c)는 **후보로 뽑혀 파일을 받은 뒤**에 돈다. (c)에서 떨어지면
> **자동으로 다음 후보로 넘어간다** — 사람이 다시 고르러 오지 않아도 된다.
> 실측 사유(번인 과다·대사 없음)는 아카이브에 기록돼 다음부터 순위가 내려간다.

**차단은 보수적으로, 되돌릴 수 있게.**
- LLM 이 막은 것은 화면에서 사람이 **허용(allow)** 으로 뒤집을 수 있다.
- 차단 사유는 **항상 기록**된다 — "왜 이 편은 안 뜨지" 가 답변 가능해야 한다.
- 신호가 없으면(LLM 실패·설명 비어 있음) **막지 않고 경고만** 한다.
  `combine_scores` 가 이미 없는 신호를 가중치 재정규화로 흡수하는 것과 같은 태도다.

#### 게이트 2 — 순위 (지금 올리기에 적당한)

`jp_score.combine_scores` 를 그대로 쓴다. 신호 4개는 이미 있고, 3개를 더한다.

| 신호 | 있음? | 무엇 |
|---|---|---|
| `views` | ✅ `log_norm` | 원본 조회수(롱테일 log 정규화) |
| `like_ratio` | ✅ `like_norm` | 좋아요율(5% = 1.0 상한) |
| `jp_comments` | ✅ `kana_ratio` | 댓글 가나 비율 — 이미 일본에서 보고 있다는 신호 |
| `llm_jp_fit` | ✅ `llm_component` | 일본 적합도 − 언어 의존도 |
| `timing` | ★ 신설 | 지금이 그 소재의 철인가. 계절 태그 없으면 중립 |
| `diversity` | ★ 신설 | 최근 발행 N편과 소재·시리즈가 겹치면 감점 |
| `kpi_feedback` | ★ 신설 | 우리 JP 채널에서 **실제로 잘 된 편**과의 유사도. `kpi_snapshots` 테이블이 이미 있다 |

> **"옛날 것부터"를 순위로 지킨다.** 최신이 무조건 좋은 게 아니다 — `diversity` 가
> 최근 발행분의 원본 공개일 분포를 보고 **안 쓴 시기 쪽에 가산**한다. 그러지 않으면
> 최신 100편만 돌다 끝나고 1,000편이 영영 안 나온다.

#### 자동화 수준 — 어디까지 기계가 하는가

| 수준 | 선별 | 준비(다운로드·현지화) | 발행 |
|---|---|---|---|
| `manual` | 추천만 | 사람이 지시 | 사람 |
| `assist` | 1순위 자동 제안 | 사람이 승인하면 | 사람 |
| **`auto`** (기본) | **1순위 자동 선택** | **자동으로 체인까지** | **사람** |

**기본은 `auto` 다** — 사용자 지시("골라서 올리게")를 그대로 따른다.
아침에 오면 오늘 몫이 **현지화까지 끝난 채 검수함에 올라와 있다.**

🛑 **`발행` 열은 어느 수준에서도 사람이다.** §8-6 회귀 0 계약(자동 공개 없음 ·
업로드는 unlisted · 공개는 사람)은 이 기능으로 완화되지 않는다. 폐기하기로 한
`auto_approve` 는 **발행 승인 자동화**였고, 여기서 되살아나는 것은 **선별**뿐이다.

하루 편수는 `per_day: 1`(기존 값) 유지 — 공개 슬롯도 하루 1편 페이스다.

#### 추천 카드에 담기는 것

점수만 보여주면 사람이 승인할 근거가 없다. 카드마다:

- 썸네일 · 제목(한국어 원문 + 일본어 초벌) · 길이 · 원본 공개일
- **왜 1순위인가** — 신호별 기여도 분해(조회수 0.82 · 일본 댓글 0.41 · 시의성 1.0 …)
- **통과한 게이트**와 **경고**(예: `wordplay` 경고 — 번역 난이도 높음)
- **예상 라우트**(`level_guess` → 실측 후 확정)
- 원본 유튜브 링크(사람이 직접 볼 수 있게)

### 5-7. 내용 중복 — 원장이 못 막는 구멍

원장은 `video_id` 로만 중복을 막는다. 원 채널이 같은 내용을 새 id 로 다시 올리면
(컴필레이션·리업로드) **이미 일본 채널에 올린 편을 또 올린다.** 실제로 캐릭터 채널에서
흔한 패턴이고, 지금 구조에서는 잡히지 않는다.

3단 판정으로 막는다. 모두 **메타만으로** 되므로 파일이 없어도 돈다.

| 단계 | 판정 | 처분 |
|---|---|---|
| 1 | 제목 정규화 일치 (공백·기호·이모지·`#태그`·`[]` 제거 후 동일) | 중복 후보 |
| 2 | 길이 차 `≤ 2초` | 중복 후보 → 확정 |
| 3 | 썸네일 pHash 해밍거리 `≤ 6` | 확정 |

- 1·2 가 동시에 맞거나 3 이 맞으면 **게이트 0 에서 제외**하고, 화면에는
  "이미 올린 〈원본 제목〉과 같은 내용으로 보입니다" 와 함께 **사람이 뒤집을 수 있게** 남긴다.
- ⚠ **자동으로 지우지 않는다.** 오탐이면 소재 하나가 영영 사라진다 — 표시하고 사람이 정한다.

## 7. 편집실 계약 — KO/JA 병기 + 줄 단위 선택 (결정 4)

### 7-1. 자료: `ko_ja_pairs` 를 편집실 정본으로 승격

지금은 검수 카드의 참고 표시용(40건 상한)이다. 이관 후에는 편집 대상 자료가 된다.

```json
{ "i": 12, "kind": "subtitle|telop|tts|title",
  "start": 34.2, "end": 36.0,
  "ko": "이거 진짜 미쳤다",
  "ja": "これマジでヤバい",
  "src": "engine|ko_edited|ja_edited",
  "use": true }
```

- `src` 가 화면에 보인다 — 검수자가 "이 줄은 내가 일본어를 직접 고친 줄" 을 안다.
- 상한 40건 해제(편집 자료이므로 전량). 크면 `editor_assets` 처럼 별 테이블로.

### 7-2. 제출 오버라이드

`edit_overrides.localize.lines[]` — 기존 스키마에 **새 키로만** 얹는다
(구 엔진은 모르는 최상위 키를 무시한다 — E6-0·E9 와 같은 구도).

```json
{"localize": {"locale": "ja", "lines": [
  {"i": 12, "ko": "이거 진짜 미쳤다니까"},    // 한국어 수정 → 그 줄만 재번역
  {"i": 15, "ja": "これはヤバすぎる"},        // 일본어 확정 → 재번역 건너뜀(pin)
  {"i": 18, "use": false}                      // 그 줄 제외
]}}
```

**규칙(엔진·화면 공통 계약):**
1. `ja` 가 오면 그 줄은 **번역하지 않는다.** 사람 확정이 LLM 을 이긴다.
2. `ko` 만 오면 그 줄만 재번역한다. 다른 줄은 캐시에서 그대로 온다.
3. 둘 다 오면 `ja` 가 이기고, 화면이 "한국어 수정은 원문에만 반영됩니다" 라고 알린다.
4. **`ko` 수정은 한국어판 산출물도 바꾼다** — 자막·내레이션이 함께 바뀌므로
   ai-video 재렌더가 필요하다(0066 체인). `ja` 만 고친 라운드는 **localize 단계만**
   다시 돌면 된다. 비용·시간이 한 자릿수 배 차이라 화면이 소요 시간을 다르게 안내한다.
   - overlay(잔망 쇼츠)는 `ko` 수정도 더빙 재합성을 부르므로 어느 쪽이든 전체 재실행이다.

### 7-3. 줄 단위 번역 캐시 (요금)

`sha1(ko + glossary_ver + model + 문맥키)` → `<job>/localize_<locale>/tcache/{key}.json`.
안 고친 줄은 재번역하지 않는다. E12 가 TTS 에서 같은 이유로 캐시를 넣었고,
편집 라운드가 반복되는 구조라 캐시가 없으면 요금이 라운드 수만큼 곱해진다.
⚠ **문맥 통번역과 충돌**한다 — 줄 단위 캐시는 앞뒤 문맥이 바뀌면 무효여야 한다.
문맥키 = 인접 ±2 줄의 ko 해시. 이 규칙은 실측으로 검증하고 실패하면 전량 재번역으로 후퇴한다.

### 9-3. 🛑 세션 간 조율 규칙 (2026-08-24 신설)

이 이관은 **여러 세션이 동시에** 만지고 있다. 8/23~24 에 실제로 일어난 것:

- vlp 가 이식 중에 **두 번** 앞서갔다(`1da2a16`·`2f338e3` → P2b, `0757b68` E16 → P2b 후속).
  매번 이식본이 뒤처졌고 따라잡아야 했다.
- 마이그레이션 번호가 **한 번 충돌**했다(내 0075·0076 vs 다른 세션의 0075·0076).
  `ON CONFLICT DO NOTHING` 때문에 대장 기록이 **조용히 삼켜져** DB 객체는 있는데 흔적이
  없었다. 0077~0079 로 재발번하고 대장을 교정했다.
- 다른 세션이 내 0078 누락(수집기 설정 행)을 **0080 으로 보완**했다 — 행이 없으면 사람이
  켤 수단이 없었다.

그래서 규칙 셋:

1. **rerender 신규 작업은 ai-video `app/localize/` 에만.** vlp `scripts/localize_run.py` 는
   컷오버로 죽었다 — 거기 고치면 아무 데도 안 나가고 이식 부채만 는다.
2. **마이그레이션 번호는 `git ls-tree origin/main` 으로 확인하고 딴다.** 로컬 브랜치의
   마지막 번호는 근거가 아니다. 적용 후 `applied_migrations` 에 내 행이 실제로 들어갔는지
   **조회로 확인**한다(`ON CONFLICT DO NOTHING` 이 삼킨다).
3. **어느 엔진이 돌았는지는 `result.localize_engine` 과 `engine_sha.localization` 으로만
   판정한다.** 두 엔진의 stdout 은 이식이 충실해 `[L4]`·`[L5]` 줄이 똑같다 — 로그로는
   구분이 안 된다.

각 P 는 **독립 배포 가능**하고 되돌릴 수 있어야 한다
(`deployments.auto_update=true` — main 머지 = 맥미니 6대 즉시 갱신).

1. `updater` 의 pip sync 실패 시 **이전 venv 를 유지**하는지 먼저 확인·보강한다.
   부분 설치된 venv 로 계속 도는 것이 최악이다.
2. 한 번에 넣지 않는다 — P1(추가 의존성 0) → P4(무거운 것) 순서.
3. 노드 1대(카나리아)에 먼저 pin 하고 3일 주행 후 확대.
4. paddlepaddle 은 macOS arm64 에서 이력이 나쁘다(8/12 초기화 실패로 하루 처리량 0).
   실측 실패 시 **OCR 백엔드를 rapidocr 기본 + paddleocr 선택**으로 뒤집는다.

### 10-2. 유튜브 수집
API 쿼터는 넉넉하나(0.5%/일) 키가 없으면 yt-dlp 폴백이고 그건 차단 위험이 있다.
`QuotaExceeded` 는 이미 일시 장애로 분류돼 있다 — 그 계약을 유지하고,
**연속 실패 시 아카이브를 비우지 않는다**(빈 응답 = 삭제로 오해하면 목록이 날아간다).

### 10-3. LLM 비결정성
번역·텔롭 추출은 런마다 다르다. 회귀 대조는 **번역 결과를 고정 입력으로 주입**해
렌더 계층만 본다. 번역 품질은 사람 검수·역번역 QA 로 따로 본다.

### 10-4. 시간축
컷·오프셋 수식을 베끼지 않는다. E13 교훈대로 **같은 함수**
(`remap_transcript_to_edited_timeline`)를 다시 태운다. E9 `cuts` 도 같은 규칙으로 흡수.
