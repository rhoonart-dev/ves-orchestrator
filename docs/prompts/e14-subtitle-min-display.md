# E14 — 자막 최소 노출 시간: 읽기 속도 하한 (ai-video 엔진 발주서)

ai-video(rht-22/ai-video) 엔진 세션용 작업 프롬프트. E13 실렌더 검증(2026-08-23)에서
드러난 결함 하나. **E11/E13 과 달리 이건 두 백엔드 공통 경로다 — 플래그 뒤에 숨을 수 없다.**

먼저 읽어라: `app/modules/subtitle.py` 의 `merge_subtitle_segments`(579~) ·
`app/pipeline.py` 의 두 호출부(3309, 3934) · `app/modules/edit_overrides.py:236~246`
(겹침을 왜 검사하지 않는지). 계약을 확정한 뒤 구현해라.

## 증상 — 읽을 수 없는 자막이 나간다

`channel_transcribe` 를 켜고 가왕쇼 채널을 elevenlabs 로 돌린 첫 실렌더
(work_order `e170d2e9…`, 쇼츠 1편 18줄). 1초 미만이 5줄이고 그중 둘은 못 읽는다.

```
 6   17.42~ 17.94 (0.52s) 박수!                                   ← 감탄사, 정상
 9   32.02~ 32.09 (0.07s) 수도.                            ◆저확신 ← 한 프레임 스침
10   33.11~ 33.83 (0.72s) 활짝 예쁜 웃음 짓는 내색 꿈에도 미련      ← 18자를 0.72초 = 25자/초
```

`박수!`(0.52s)는 짧은 감탄사라 **정상이다 — 이런 건 건드리지 마라.** 문제는 9번(0.07초)과
10번(25자/초)이다. 둘 다 노래 구간이고, Scribe 의 word timestamp 가 노래에서 흔들렸다.

## 원인 — `min_duration_sec` 은 하한이 아니라 병합 힌트다

`app/modules/subtitle.py:729`:

```python
if (cur.end_sec - cur.start_sec) < min_duration_sec and gap <= max_gap_sec:
    should_merge = should_merge or len(combined_text) <= effective_max_chars
```

`min_duration_sec=0.6` 은 "너무 짧으면 되도록 다음 것과 합쳐라"일 뿐이고 **`gap <= 0.25s`
일 때만 발동한다.** 9번은 다음 cue 까지 1.02초 떨어져 있어 병합 대상이 아니었다. 그리고
**cue 를 늘려 주는 코드는 아예 없다** — 고립된 짧은 cue 는 그대로 화면에 나간다.

두 호출부 모두 `min_duration_sec` 을 넘기지 않으므로 기본값 0.6 을 쓴다.

## ⚠ 배포 특성 — 이번엔 게이트가 없다

ai-video 는 `deployments.auto_update=true` 이고 핀이 없다. **main 에 머지하면 version_watch
(시간당 1회)가 새 sha 를 보고 맥미니 6대가 다음 claim 경계에서 자동으로 갱신한다.**

E11·E13 은 `--transcribe-backend elevenlabs` 경로 안에 있어 미지정 실행이 안전지대였다.
**이번엔 아니다.** `merge_subtitle_segments` 는 모든 생성이 지나는 길이라, 여기서 어긋나면
**전 채널 자막 타이밍이 한 번에 바뀐다.** 회귀 범위를 스스로 정의하고 증명해라 —
"안 바뀐다"가 아니라 "무엇이 바뀌고 무엇이 안 바뀌는지"를 수치로 내놔야 한다.

## E14-0. 먼저 확인할 것 (구현 전)

**① 겹침은 정상 데이터다 — 고치지 마라.** `edit_overrides.py:236~246` 에 실측 기록이 있다:
`merge_subtitle_segments` 가 겹치는 cue 를 만들고(피의_게임_X_9d2d1b85 는 20건 중 여러 쌍이
겹쳤다 — `0.2~3.67` 과 `1.7~5.3`) ASS 도 그대로 그린다. 편집실이 겹침 검사를 넣었다가
걷어낸 이유가 그것이다.

따라서 "다음 cue 시작을 침범하지 않게" 같은 규칙을 **전면 적용하면 기존 겹침을 건드려
회귀가 난다.** 늘리는 것은 **빈 구간(다음 cue 가 현재 end 보다 늦게 시작하는 경우)** 으로만
제한하고, 이미 겹쳐 있는 쌍은 손대지 마라. 실제 데이터에서 겹침 비율이 얼마인지 먼저 세라.

**② 편집실 경로는 범위 밖이다.** `edit_overrides` 는 전량 교체 규약이라 사람이 정한
start/end 가 그대로 나간다. **사람이 0.3초로 정했으면 그게 의도다** — 렌더 단계(`build_ass`)
에 하한을 넣으면 그 의도를 덮어쓴다. 하한은 **전사 경로**(`merge_subtitle_segments`)에 둔다.
다르게 판단했다면 근거를 보고에 써라.

**③ 두 호출부의 `max_total_chars` 가 다르다** — 3309 는 40, 3934 는 config 계산값. 하한을
글자수 기준으로 만들 거라면 이 차이가 결과에 어떻게 반영되는지 확인해라.

## E14-1. 읽기 속도 하한 (본체)

**시간 하한이 아니라 읽기 속도 하한이다.** 10번은 0.72초로 `min_duration_sec=0.6` 을
넘기지만 25자/초라 못 읽는다. 한국어 자막 관례는 대략 **12~14자/초**다(값은 네가 정하고
근거를 써라 — 이 저장소에서 외부 조사가 막혀 있으면 보수적으로 잡고 그렇게 적어라).

- cue 의 최소 노출 시간을 `max(절대 하한, 글자수 / 초당 글자수)` 로 잡는다.
- 모자라면 **`end_sec` 를 늘린다**. 늘릴 수 있는 한도는 E14-0 ①의 제약을 따른다
  (빈 구간으로만, 이미 겹친 쌍은 그대로).
- 늘려도 모자라면 **그 사실을 로그에 남겨라.** 조용히 포기하면 '고쳤는데 왜 그대로지'가 된다.
- `start_sec` 는 건드리지 마라 — 소리와 자막이 어긋난다.
- `max_duration_sec=6.0` 상한과 충돌하면 상한이 이긴다(6초 넘게 늘리지 않는다).

**짧은 감탄사는 예외로 살려라.** `박수!`(0.52s·3자)는 정상이고, 글자수 기준 하한이면
자연히 통과한다(3자면 0.25초면 족하다). 절대 하한을 크게 잡아 감탄사까지 늘이면
장면이 지나간 뒤에도 자막이 남는다.

## E14-2. 곁다리 — 주석이 실제와 다르다

`app/modules/stt_elevenlabs.py:67`:

```python
_CUE_MAX_CHARS = 44         # merge_subtitle_segments 의 max_total_chars 와 동일
```

실제로는 파이프라인이 `max_total_chars=40` 으로 부른다(`pipeline.py:3309`). 동작 오류는
아니지만(Scribe 가 44 로 묶고 merge 가 40 으로 다시 묶는다) 주석이 틀렸다. 값을 맞추든
주석을 고치든 하나로 정리해라.

## E14-3. 실측 검증 (필수)

**회귀 범위 증명이 이 발주의 절반이다.** 공통 경로라 "안 깨졌다"를 말로 하면 안 된다.

1. **못 읽는 줄이 사라졌는가** — 가왕쇼 EP2 와 같은 조건으로 다시 뽑아, 1초 미만 줄
   전량과 각 줄의 **자/초**를 내라. `수도.`(0.07초)·`활짝 예쁜…`(25자/초)이 어떻게 됐는지
   건별로. `박수!` 같은 감탄사가 부당하게 늘어나지 않았는지도 같이.
2. **겹침이 늘지 않았는가** — 수정 전후 겹치는 cue 쌍 수를 세서 비교해라. 늘었으면 E14-0 ①
   제약이 깨진 것이다.
3. **whisper 경로 회귀** — `--transcribe-backend` 없는 실행. 같은 소스로 수정 전후 자막을
   뽑아 **줄 수·각 줄의 start/end/text 를 대조**해라. 바뀐 줄이 있으면 전량 목록으로 내고
   왜 바뀌었는지(원래 하한 미달이었다) 설명해라. **여기서 "0건"이 나오는 게 정상은 아니다**
   — whisper 도 짧은 cue 를 내면 늘어난다. 몇 줄이 왜 바뀌었는지가 답이다.
4. **여러 편에서 재라** — 한 편만 보고 결론 내지 마라. 최소 3편, 성격이 다른 것으로
   (대사 중심 · 노래/배경음악 · 짧은 감탄사가 많은 편). E11 에서 한 편만 보고 낸 결론이
   두 번째 편에서 뒤집힌 전례가 있다.
5. **cue 수·길이 분포** — 수정 전후 p50/p90/max 와 1초 미만 비율. 분포가 통째로 밀렸으면
   하한이 과하다.
