## 2. 3중 게이트 — 왜 이렇게 나눴나

목록 1,100편은 사람이 못 고른다. 그렇다고 자동으로 고르면 왜 그게 골라졌는지 아무도
모른다. 그래서 **되돌릴 수 없는 것 · 사람이 뒤집을 수 있는 것 · 그냥 순위**를 나눴다.

### 게이트 0 — 제외 (자동 · 되돌릴 수 없음)

사용자 지시의 "이전에 올렸던 것은 제외"가 사는 자리다.

| 사유 | 근거 |
|---|---|
| 이미 발행 (`youtube_id` 또는 `state='uploaded'`) | vlp 원장 R10 이관 |
| 내용 중복 (`dup_of`) | 제목 정규화 후 길이 ±2초 일치 |
| 진행 중 (`processing`·`pending_approval`·`approved`·`selected`) | 두 번 걸리면 안 된다 |
| 규격 밖 (길이 미상·너무 짧음) | 수집기가 선반에 안 넣는다 |

**3중으로 막는다** — 화면이 버튼을 안 내고, RPC 가 거절하고, 0076 트리거가 거절한다.
실측 확인: `uploaded` 되돌리기와 `youtube_id` 덮어쓰기 모두 트리거에서 막혔다.

⚠ 내용 중복만 오탐 해제(`p_clear_dup`)가 열려 있다 — 제목이 같은 별개 편이 있을 수 있다.

### 게이트 1 — 문제 소지 (사람이 뒤집을 수 있음)

이 단계에서 **새로 만든 것은 이것뿐**이다. 신뢰도 순으로 세 층이다.

1. **차단 목록** (`ops_config.loopy_denylist`) — 사람이 관리. LLM 이 못 푼다.
2. **LLM 플래그** — `collab`·`sponsored`·`music`·`event` 는 차단,
   `topical`·`wordplay` 는 감점(0.10/건).
3. **실측** — 계절 소재는 ±3주 창 밖이면 차단(연말 소재의 해 넘김 포함).

차단은 근거지 판결이 아니다 — reviewer 가 카드에서 되살릴 수 있고, 누가 되살렸는지
`allowed_by` 에 남는다.

### 게이트 2 — 순위 (지금 올리기 적당한)

vlp `src/jp_score.py` 의 신호 결합·정규화를 **값까지 그대로** 옮겼다.

| 신호 | 가중 | 없으면 |
|---|---|---|
| 조회수 (log 정규화) | 0.25 | — |
| 좋아요율 | 0.15 | — |
| 일본 반응 비율 | 0.15 | 가중치 재정규화 |
| LLM 일본 적합도 | 0.20 | 가중치 재정규화 |
| 시의성 (계절) | 0.10 | — |
| 다양성 | 0.10 | — |
| 성과 학습 | 0.05 | 가중치 재정규화 |

**없는 신호는 0점이 아니라 가중치 재정규화**다 — 0 으로 세면 아직 신호가 없는 초기에
전 후보가 똑같이 깎여 순위가 무의미해진다.

`diversity_signal` 이 "옛날 것부터"를 지킨다: 최근 발행분의 **원본 공개일**과 시기가
몰리면 감점한다. 우리 발행일이 아니라 원본 공개일을 보는 것이 핵심이다.

## 3. 점수와 추천을 나눈 이유

`state='scored'` = 오늘의 추천(상위 top_n), `score` = 정렬 재료(막히지 않은 편 전량).

처음엔 상위 top_n 에만 점수를 썼다. 그러면 대시보드 '점수순' 정렬이 5개짜리 목록이
되어 아카이브를 훑는 쓸모가 사라진다. 상위에서 밀려나면 추천 표시를 **걷는다** —
안 걷으면 추천이 날마다 쌓인다.

## 4. 화면 — 고를 수 있어야 완료다

`dashboard/index.html` '소재 아카이브' 탭.

- **추천 카드에 신호 분해 막대**를 같이 그린다. 점수만 보여 주면 승인할 근거가 없다.
- **제외된 편도 사유와 함께** 보인다 — "왜 이 편은 안 뜨지"가 답변 가능해야 한다.
- 필터 5 · 정렬 4 · 60편 페이징. 1,100행을 15초 자동 갱신에 얹지 않고 **탭을 열 때만**
  받는다(지난 날짜 신호등 `boardPast` 와 같은 규율).
- 선별기가 꺼져 있으면 "추천이 없다"가 아니라 **꺼져 있다고** 적는다.

실측(임시 행 6건, 전량 롤백): 필터 4갈래가 정확히 갈리고, 사람이 되살린 편이

## 5. 🛑 운영 발견 2건 (P3 범위 밖이지만 지금 알아야 한다)

### 5-1. `localize_engine` 스위치가 **아무 데도 연결돼 있지 않다**

`ops_config.localize_engine` 이 `{"_default":"vlp","SHOTCONE":"ai-video"}` 로 바뀌어
있다(8/23 16:39). 그런데 **읽는 코드가 배포돼 있지 않다.**

- 스위치를 읽는 `pick_engine` 은 P2 커밋 `63f70a5` 에 있고, 이 커밋은 작업 브랜치에만
  있다(main 미머지).
- 노드가 도는 오케스트레이터는 `9bd2164` — `grep ENGINE_SWITCH` 결과 0건.
- 실증: 8/24 00:00 SHOTCONE 잡(`ff823804`)이 **성공**했는데 결과의
  `localize_engine` 이 `null` 이고 `engine_sha.localization = 5f8c3e3` 가 찍혔다.
  vlp 레포 SHA 가 찍혔다는 것은 **vlp 로 돌았다**는 뜻이다.

⚠ 두 엔진의 stdout 은 내가 그대로 이식해서 `[L4]`·`[L5]` 줄이 **똑같다** — 로그로는
구분이 안 된다. `engine_sha.localization` 과 결과의 `localize_engine` 만이 근거다.

**지금 상태:** 스위치는 켜져 있다고 믿기는 값이 들어 있지만 실제로는 vlp 가 돈다.
회귀는 없다(아무것도 안 바뀌었으니까). 다만 **컷오버가 됐다고 오해하면 안 된다** —
P2 커밋이 main 에 머지되어 노드에 배포된 뒤라야 스위치가 의미를 갖는다.

### 5-2. vlp 폰트 복사 버그가 **운영에서 실제로 터지고 있다**

P1 에서 찾아 이식본에서 고친(`copy2` → `copyfile`) 그 버그다. 잠재 버그가 아니었다.

- localize 잡 17건 중 **4건(24%)** 이 `_provision_fonts` 의
  `shutil.copy2 → PermissionError` 로 1차 실패했다.
- 8/13 · 8/15 · 8/18 · 8/22, 노드 4대(mm-02·03·05·06)에 걸쳐 있다.
- 전부 재시도로 성공했지만 값을 치른다 — 8/22 잡은 6시간 45분 걸렸다(평시 ~1.5시간).

원인은 `copy2` 가 macOS SIP 플래그를 `chflags` 로 함께 복사하려 드는 것이다.
`app/localize/rerender.py` 는 `copyfile` 을 쓴다. **이관이 이 버그를 함께 고친다** —
컷오버의 부수 효과가 아니라 이유 하나다.
