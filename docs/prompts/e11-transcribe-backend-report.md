## ① 표기 보존 — 5/5, 그리고 **어느 장치가 무엇을 고쳤는지** 갈렸다

커리어데이 EP8. (가왕쇼에는 이 낱말들이 안 나와 전 판 0 이다 — 정상.)

| | whisper | Scribe kt **off** | Scribe kt **on** | 고친 장치 |

| SK텔레콤 | 1 | 0 | **1** | keyterms |

\* 집계는 0 이지만 **실제로는 살았다.** 원문 확인:

```
whisper       IT업계에서
Scribe kt off 아이티            ← 풀어씀
Scribe kt on  IT                ← 뒤가 공백 = 'IT 업계에서'
```

whisper 와 다른 건 **띄어쓰기뿐**이고 자막으로는 둘 다 정상이다(맞춤법상 띄어 쓰는 쪽이
맞다). 집계 문자열이 `IT업계` 붙여쓰기만 세어 놓쳤다.

덤으로 우리가 못 봤던 건들도 잡혔다 — `십퍼센트에→10퍼센트에`(EP8), `십분→10분`(가왕쇼).

**P1 은 닫혔다.**

## ② 언어 이탈 — 오탐 0 이지만 **차단이 실증되지 않았다**

두 편 · 두 판 모두 **버린 줄 0건**. 멀쩡한 한국어를 하나도 안 버렸다는 뜻이니 오탐
0 조건은 만족한다.

그러나 **E13 을 발주하게 만든 `謝 謝` 가 이번 실행에는 아예 나오지 않았다.** 8/22 판에서
저확신 3건 중 하나로 나왔던 그 줄이, 같은 소스·같은 구간에서 재현되지 않았다(Scribe 는
같은 입력에도 출력이 달라진다 — 저확신 목록 자체가 두 판에서 서로 다르다).

즉 지금 근거로는 **"차단이 잘 돌아 `謝 謝` 를 잡았다"고 말할 수 없다.** 말할 수 있는 것은
"이번엔 이탈이 나오지 않았고, 판정기가 정상 한국어를 오탐하지 않았다" 까지다. 차단
동작 자체는 엔진 단위 테스트(`tests/test_e13_transcribe_polish.py`)가 지키고 있다.

**저확신 26건(두 판 각 13건) 전량을 확인했다 — 이탈 문자 0건.** 한글·라틴·숫자·문장부호
밖 문자가 하나도 없다(`Wow.` 는 라틴이라 정상). 판정기가 놓친 것이 아니라 이탈 자체가
없었다.

그리고 그 목록이 **E13 의 설계 판단을 뒷받침한다** — 잡힌 줄이 `네.` · `뭐야?` ·
`안녕하세요.` · `본인 자체가 일등이라면은.` 같은 멀쩡한 대사다. logprob 임계로 잘랐다면
전부 사라졌을 것이다. '버리지 말고 표시만'이 옳았다.

## ④ 회귀 0 — 해시 대조는 **못 했다**, 대신 두 갈래로 검증했다

발주서가 요구한 것은 파이프라인 작업 두 건 + `--diff JOB_A JOB_B`(다섯 산출물
sha256 비교)다. 그건 **구 엔진 시절 잡 디렉터리가 남아 있어야** 성립하는데 확보하지
못했다. 대신:

**전사 경로 — 코드가 안 닿는다.** `speech.py`·`merge_subtitle_segments` 무변경.
`stt_elevenlabs.py` 는 elevenlabs 경로에서만 import. `pipeline.py` 변경은 전부 게이트 뒤:

```python
if backend != "elevenlabs" or not final_segments or not clips:   # _flag_low_confidence_segments
if backend_name == "elevenlabs" and low_confidence_out is not None:
```

**TTS 경로 — 여기는 게이트가 없어 위험했다.** `tts.py` 의 fail-loud 전환(모르는 라벨이
조용한 폴백 대신 즉시 실패)은 **모든 실행**에 영향이 간다. 그래서 실데이터를 조회했다:

| voice | 건수 | speed | 건수 |
|---|---|---|---|
| ko_female_high | 42 | (없음→normal) | 50 |
| ko_female | 19 | fast | 36 |
| ko_male_low | 14 | normal | 3 |
| ko_male | 14 | | |

엔진 프리셋은 `ko_female · ko_female_high · ko_male · ko_male_low · chat_emma ·
chat_brian · chat_seraphina · chat_florian` 이고 **`VOICE_PRESETS` 와 `EL_VOICE_PRESETS`
키 집합이 동일**하다(속도표도 5개로 동일). 살아 있는 값이 전부 그 안에 있으므로
**폭발 반경 0**. 구 체크포인트의 `narrative_female` 은 `LEGACY_VOICE_ALIASES` 가 오늘과
같은 곳으로 보낸다.

**판정: 해시로 증명하지는 않았다.** 코드 범위와 실데이터 어휘로 "달라질 곳이 없다"를
보인 것이다. 게이트를 켜기 전 한 번은 해시 대조를 하는 편이 낫다.

| | 전사 단계 (A/B 도구) | **최종 자막** (merge 후) |
|---|---|---|
| p50 | 0.84s | **2.04s** |
| p90 | 2.54s | 3.52s |

**`merge_subtitle_segments` 가 제 몫을 한다.** 0.84s 로 잘게 끊긴 전사가 최종 자막에서는

수치로 자막 품질을 판정하면 안 된다는 것이 확인됐다.

**대신 다른 결함이 드러났다 — 아래 별도 절.**

## ⑥ 새 결함 — 최소 노출 시간 하한이 없다 (공통 경로)

가왕쇼 EP2 최종 자막 18줄 중 **1초 미만이 5줄(28%)**. 그중 둘은 읽을 수 없다.

```
 6   17.42~ 17.94 (0.52s) 박수!                                   ← 감탄사, 정상
 9   32.02~ 32.09 (0.07s) 수도.                            ◆저확신 ← 한 프레임 스침
10   33.11~ 33.83 (0.72s) 활짝 예쁜 웃음 짓는 내색 꿈에도 미련      ← 18자를 0.72초
```

`박수!`(0.52s)는 짧은 감탄사라 정상이다. 문제는 **9번(0.07초)** 과 **10번(18자를 0.72초,
25자/초)** 이다. 둘 다 **노래 구간**이고, Scribe 의 word timestamp 가 노래에서 흔들린 것으로
보인다.

### 원인 — `min_duration_sec` 은 하한이 아니라 **병합 힌트**다

`app/modules/subtitle.py:729`:

```python
if (cur.end_sec - cur.start_sec) < min_duration_sec and gap <= max_gap_sec:
    should_merge = should_merge or len(combined_text) <= effective_max_chars
```

`min_duration_sec=0.6` 은 "너무 짧으면 되도록 다음 것과 합쳐라"일 뿐이고, **`gap <= 0.25s`
일 때만 발동한다.** 9번은 다음 cue 까지 1.02초 떨어져 있어 병합 대상이 아니었고, cue 를
**늘려 주는 코드는 아예 없다** — 고립된 짧은 cue 는 그대로 화면에 나간다.

**이건 elevenlabs 전용 결함이 아니다.** `merge_subtitle_segments` 는 두 백엔드 공통 경로다.
다만 Scribe 는 word 단위 경계라 고립된 짧은 cue 가 훨씬 자주 생겨 **이 구멍을 드러낸다.**

### 필요한 것

시간 하한이 아니라 **읽기 속도 하한**이다. 10번은 0.72초로 0.6 하한을 넘기지만 25자/초라
못 읽는다(한국어 자막 관례는 대략 12~14자/초). 다음 cue 시작을 침범하지 않는 선에서
`end_sec` 를 글자수 기준 최소 노출 시간까지 늘려야 한다.

### 저확신 표시는 제 몫을 했다

저확신 3줄(8·9·11번)이 **전부 그 노래 구간**이다. 편집실 ◆ 배지가 검수자를 정확히 그리로
보낸다 — P2-b 가 의도한 그대로다. 다만 10번(타임코드만 깨지고 logprob 은 정상)은 못 잡는다.
logprob 은 '잘 들었나'이지 '타임코드가 맞나'가 아니다.

**곁가지 관찰(표본 1)**: 가왕쇼 첫 cue 가 keyterms off 에서 `제1대 현역가왕 전유진!`,
on 에서 `제일 대 현역가왕 전유진!` 으로 **나빠졌다**. `현역가왕` 을 키텀으로 준 것이
앞 낱말 표기에 영향을 준 것으로 보인다. 표본 하나라 단정하지 않는다.

## 결론

E13 은 발주한 두 가지를 실제로 고쳤다 — **표기는 5/5 로 닫혔고**(keyterms 와 사전이
각각 제 몫을 했다), 판정기는 정상 한국어를 오탐하지 않는다. 속도(9~12배)·요금
($0.27/시간)·이벤트 누출 0·싱크 일치는 두 편에서 일관된다.

남은 것은 둘인데 성격이 다르다.

1. **회귀 0 해시 대조** — 코드로는 안 닿는 게 확인됐지만 증명은 아니다.
2. **⑥ 최소 노출 시간 하한** — 실렌더에서 드러난 새 결함. 공통 경로(`merge_subtitle_segments`)
   라 elevenlabs 를 끌 이유는 아니지만, 노래가 많은 편에서는 읽을 수 없는 줄이 나온다.

둘 다 "일레븐랩스가 나쁘다"는 근거는 아니다. 오히려 가왕쇼에서는 whisper 쪽이
38.54초 cue 를 내고 우승자 이름을 뭉갠다. 그래서 게이트를 켜는 방향은 유지하되,
**켠 뒤 첫 편을 사람이 확인하는 것**을 조건으로 둔다.

## 권고

### 실제 적용 (2026-08-23)

`ops_config.channel_transcribe = on`. 첫 전환 채널은 **HANIPJUMAK(한 입 주막 · 가왕쇼)** —
`channel_design_overrides.design.transcribe_backend = 'elevenlabs'`. 배경음악 구간에서 내장
whisper 가 38.54초 cue 를 내고 우승자 이름을 뭉개는 것이 이 채널 소스에서 실측됐다.

주의 둘:

- **다음 생성부터 적용된다.** 전사는 생성 초반 단계라 편집실 재렌더(from_step=resources|render)
  에는 반영되지 않는다 — 0072 가 이 키를 편집실이 아니라 채널에 둔 이유가 그것이다.
- 채널 오버라이드는 **통째 교체**(`effective_design`)라 기존 레이아웃 키 13개를 그대로 두고
  키 하나만 더했다. 어댑터가 이 design 으로 `--transcribe-backend elevenlabs` 를 포함한
  13쌍 플래그를 예외 없이 만드는 것까지 확인했다.

첫 편 완성본에서 **자막 줄 길이**를 확인할 것 — ⑤ 에서 보류한 그 항목이다.

---

`channel_transcribe = on` 은 **선택칸을 화면에 띄울 뿐** 어느 채널도 바꾸지 않는다 —
채널 템플릿의 `transcribe_backend` 는 손대기 전까지 `default` 다. 그래서 게이트 자체는
켜도 안전하고, 실제 전환은 **배경음악이 많은 채널 한 곳부터** 한다. whisper 손실이
제일 큰 곳이라 이득이 가장 크고, cue 분포 우려도 그 채널에서 제일 먼저 드러난다.
첫 편 완성본을 보고 자막 줄 길이가 실제로 읽을 만한지 확인한 뒤 넓힌다.
