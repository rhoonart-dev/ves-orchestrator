### 어절 일치율 85.8% 의 분해 — 차이의 대부분은 청취 오류가 아니라 **표기 정책**

whisper 5,260자 / scribe 5,428자. 상위 30건 차이를 분류하면:

| 부류 | 건수(표본) | 예 | 자막 관점 |
|---|---|---|---|
| 문장부호 추가 (scribe 만) | ~9 | `모르겠는데` → `모르겠는데.` · `일하는가` → `일하는가?` | 중립 |
| 맞춤법·띄어쓰기 (scribe 정답) | 3 | `살만하니까`→`살 만하니까` · `운영해온`→`운영해 온` · `그 다음`→`그다음` | scribe 우세 |
| 청취 교정 (scribe 정답) | 2 | `눈간에`→`누구나` · `하지라고`→`하시려고` | scribe 우세 |
| 청취 오류 (whisper 정답으로 보임) | 4 | `제`→`쟤` · `살짝`→`잘` · `짠`→`쓰면` · `들을`→`될` | whisper 우세 |
| **영문 약어·숫자 한글 풀어쓰기** | 5 | `SK텔레콤`→`에스케이텔레콤` · `NC소프트`→`엔씨소프트` · `CTO`→`씨티오` · `IT업계`→`아이티 업계` · `30년`→`삼십년` | **whisper 우세 — 자막 관례 위반** |
| 필러·구어 유지 (scribe) | 7+ | `어` · `이제` 삽입, `있으면`→`있으면은`, `해봤지만`→`해봤지만은` | whisper 우세 |

**청취 정확도 자체는 사실상 동률이다** — 서로 2~4건씩 잡아낸다. 벌어진 14.2%p 는
문장부호·필러·표기 관례 차이가 만든 것이고, 그중 자막 품질에 실제로 해로운 쪽은
scribe 다(화면에 `에스케이텔레콤`, `씨티오`, `삼십년` 이 뜬다).

## 측정 2 — mm-04 / 가왕쇼 EP1 (배경음악·47분) — **mm-01 판정을 뒤집는다**

sha `e5567c94…`. 오디오 2828.6초. 예능 실조건(무대·배경음악·환호).

### 뒤집힌 것 ① — cue 방향이 반대다

mm-01 에서는 scribe 가 *적고 길었고*(206→180), mm-04 에서는 scribe 가 *많고
짧다*(898→1468). 즉 **"일레븐랩스 줄이 두 배 길다"는 mm-01 하나만 보고 내린 결론이었고
일반화되지 않는다** — 방향이 소스 성격에 따라 뒤집힌다.

### 뒤집힌 것 ② — 이 소스에서는 whisper 가 무너진다

첫 cue 비교:

```
[default   ]  10.00~ 34.70  제 1대 현역가왕, 원역가왕, 홍진!     ← 24.7초짜리 한 줄
[elevenlabs]  10.34~ 11.65  제 1대 현역가왕 전유진!             ← 1.31초
```

24.7초짜리 자막 한 줄은 그대로 못 쓴다. 내용도 whisper 쪽이 깨졌다 — `원역가왕` 은
`현역가왕` 을 되풀이하다 뭉갠 것이고 뒤의 이름도 붙지 않는다. 배경음악 위에서 whisper
가 세그먼트를 길게 늘이며 환각하는 전형적 실패다. 로그의 `문장 단위 분할 적용` 후처리
도 이걸 못 잘랐다. 그리고 whisper 는 이 편에 **19.7분**을 썼다(47분 영상, 0.42배속).

싱크는 이 소스에서도 같은 좌표계다 — 끝 cue `2811.69~2812.89 유후` vs
`2812.29~2813.91 유후!`.

### 새로 나온 결함 — scribe 언어 환각

저확신 3건 중 하나가 **중국어**다.

```
[Scribe-확신도낮음] 2175.6~2177.6s logprob=-1.17 '謝 謝 .'
[Scribe-확신도낮음] 2581.5~2582.7s logprob=-1.17 '아저씨 이때 좋아요.'
[Scribe-확신도낮음]  837.9~ 839.4s logprob=-0.91 '마음처럼.'
```

한국어 소스에 `謝 謝` 가 자막으로 박히면 안 된다. 다행히 **저확신 플래그가 잡아냈다** —
logprob 임계로 거르는 후처리를 붙이면 막힌다. mm-01(대사 중심)에서는 저확신 0건이었으니
배경음악 구간에서만 나오는 현상으로 보인다.

오디오 이벤트 누출은 **배경음악 조건에서도 0건**이다(항목 5, 더 강한 조건에서 재확인).

## 게이트를 켜기 전 남은 것 — 엔진 후처리 2건 + 미측정 1건

두 소스를 다 보고 나면 판단이 "scribe 가 나쁘다"가 아니라 **"scribe 를 쓰려면 엔진에
후처리 두 개가 있어야 한다"** 로 좁혀진다.

**P1. 고유명사·숫자 표기 보존.** scribe 가 `SK텔레콤`→`에스케이텔레콤`, `CTO`→`씨티오`,
`IT업계`→`아이티 업계`, `30년`→`삼십년` 으로 풀어쓴다(mm-01). 화면에 그대로 뜨면 안 된다.

**P2. 저확신 줄 처리.** mm-04 에서 `謝 謝 .` 같은 언어 환각이 나왔다. logprob 임계로
버리거나 재시도하는 경로가 필요하다. 플래그 자체는 이미 동작하므로 붙이기만 하면 된다.

**cue 규칙 차이는 블로커에서 내린다.** 두 백엔드의 분할 규칙이 다른 건 맞지만 방향이
소스마다 뒤집히고, mm-04 에서는 오히려 whisper 가 24.7초 cue 를 냈다. 한쪽이 일관되게
낫지 않으므로 "일레븐랩스를 막을 이유"로는 쓸 수 없다. 다만 채널마다 자막 리듬이
달라지는 건 사실이니, **채널 단위 선택**이라는 지금 설계(0072 가 편집실이 아니라 채널에
키를 둔 이유)가 맞다는 근거가 된다.

**미측정 — E11-3 항목 4(회귀 0).** A/B 도구의 사정거리 밖이다. 이 도구는 전사 단계만 두
번 돌릴 뿐 파이프라인 완성본을 비교하지 않는다. 플래그 없는 실행이 종전과 같은지는 같은
소스로 작업 두 건을 돌려 `--diff JOB_A JOB_B` 로 재야 한다.

## 결론 — `channel_transcribe` 게이트는 **off 유지**, 다만 사유가 바뀐다

두 소스에서 일관된 것: **속도 9~25배**, **$0.22/시간**, **싱크 일치**, **이벤트 누출 0**.
예능 실조건(mm-04)에서는 정확도도 scribe 가 낫다 — whisper 가 배경음악 위에서 24.7초
cue 를 내고 이름을 뭉갤 때 scribe 는 1.31초에 정확히 받았다.

막는 건 scribe 의 실력이 아니라 **다듬기 부재**다 — P1(표기 보존) · P2(저확신 줄 처리).
둘이 닫히면 채널 단위로 켤 만하고, 그때도 E11-3 항목 4(회귀 0)를 파이프라인으로 한 번
재고 나서 켠다.

**발주서: `e13-scribe-postprocess.md`** — P1·P2 와 미측정 항목 4(회귀 0)를 엔진 세션에
넘길 형태로 정리했다. keyterms 는 이미 `stt_elevenlabs.py` 에 구현돼 있고 꺼져 있다
(`ELEVENLABS_STT_KEYTERMS`) — 지금까지의 실측이 **Whisper 만 고유명사 힌트를 받는
비대칭 조건**이었다는 뜻이라, P1 은 그것부터 확인한다.

배경음악이 많은 편(가왕쇼 계열)은 whisper 쪽 손실이 커서, P1·P2 가 닫히면 **그 채널부터**
켜는 게 이득이 가장 크다.

## 실측 중 드러난 엔진 결함 2건 (E11 범위 밖, 별건 처리 필요)

- `app/modules/ffmpeg_utils.py:163` — ffmpeg 미검출 메시지가 **윈도우 설치법**을 안내한다.
  전 노드가 macOS 다. (운영 영향 없음 — 워커는 PATH 를 주입한다. 수동 실행 때만 걸린다.)
- `app/modules/tts.py:278` — `EL_VOICE_PRESETS.get(voice, EL_VOICE_PRESETS[DEFAULT_VOICE])`.
  모르는 **라벨**이 조용히 기본 목소리로 떨어진다(E12 가 고치는 `elevenlabs:` 접두사
  경로와 달리 라벨 경로는 여전히 fail-silent). E12 와 같은 규율로 즉시 실패해야 한다.

## 재현 방법

```
ssh <노드> 'export PATH=/opt/homebrew/bin:/usr/local/bin:$PATH;
  set -a; . /opt/ves/secrets/ves.env 2>/dev/null; . /etc/ves/node.env 2>/dev/null; set +a;
  cd /opt/ves/engines/ai-video && .venv/bin/python -m scripts.e11_transcribe_ab \
    --video /opt/ves/cache/sources/<sha> --json-out /tmp/e11_ab.json'
```

`ELEVENLABS_API_KEY` 는 `/opt/ves/secrets/ves.env` 에 있다(ai-video `.env` 아님 —
`ves/config.py:44-48` 이 정한 순서). 비대화형 SSH 는 PATH 에 homebrew 가 없어 ffmpeg 를
못 찾으므로 위 `export` 가 필요하다. 47분 소스는 whisper 쪽만 20분 가까이 걸리므로
`nohup … &` 로 떼어놓고 `tail /tmp/e11_ab.log` 로 본다.
