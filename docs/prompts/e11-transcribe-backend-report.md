## ⑥ 실렌더에서 나온 새 결함 — 최소 노출 시간 하한 (공통 경로) · **해결됨**

가왕쇼 EP2 최종 자막 18줄 중 **1초 미만이 5줄(28%)**. 그중 둘은 읽을 수 없다.

```
 6   17.42~ 17.94 (0.52s) 박수!                                   ← 감탄사, 정상
 9   32.02~ 32.09 (0.07s) 수도.                            ◆저확신 ← 한 프레임 스침
10   33.11~ 33.83 (0.72s) 활짝 예쁜 웃음 짓는 내색 꿈에도 미련      ← 18자를 0.72초
```

`박수!`(0.52s)는 짧은 감탄사라 정상이다. 문제는 **9번(0.07초)** 과 **10번(18자를 0.72초,
25자/초)** 이다. 둘 다 **노래 구간**이고, Scribe 의 word timestamp 가 노래에서 흔들린 것으로
보인다.

### 원인 — `min_duration_sec` 은 하한이 아니라 **병합 힌트**다

`app/modules/subtitle.py:729`:

```python
if (cur.end_sec - cur.start_sec) < min_duration_sec and gap <= max_gap_sec:
    should_merge = should_merge or len(combined_text) <= effective_max_chars
```

`min_duration_sec=0.6` 은 "너무 짧으면 되도록 다음 것과 합쳐라"일 뿐이고, **`gap <= 0.25s`
일 때만 발동한다.** 9번은 다음 cue 까지 1.02초 떨어져 있어 병합 대상이 아니었고, cue 를
**늘려 주는 코드는 아예 없다** — 고립된 짧은 cue 는 그대로 화면에 나간다.

**이건 elevenlabs 전용 결함이 아니다.** `merge_subtitle_segments` 는 두 백엔드 공통 경로다.
다만 Scribe 는 word 단위 경계라 고립된 짧은 cue 가 훨씬 자주 생겨 **이 구멍을 드러낸다.**

### 해결 (2026-08-23) — 엔진 E14 `04a3d60` (main `7f7c052`)

`merge_subtitle_segments` 꼬리에 순수 후처리 `_enforce_min_exposure` 가 붙었다.
필요 노출 = `max(0.4초, 글자수 / 12자per초)`, 6초 상한이 이긴다. **`end_sec` 만** 늘리고
(start 를 당기면 소리보다 자막이 먼저 뜬다) **빈 구간으로만** — 이미 겹친 쌍은 손대지 않고,
비어 있어도 다음 cue 시작까지만 늘린다. 늘려도 모자라면 건별로 사유와 함께 로그에 남긴다.

코드를 직접 읽어 확인한 것: `start_sec` 불가침 · 겹친 쌍 skip · `min(want_end, next_start)`
로 신규 겹침 불가 · 6초 상한 우선 · 두 상수를 0 으로 주면 무동작(비상 탈출구) ·
`sorted(key=(start_sec,end_sec))` 뒤라 `out[i+1]` 이 시간순 다음 cue 가 맞다.

엔진이 낸 회귀 범위(저장된 실렌더 45편 639줄, 전부 whisper 경로):
**76줄(11.9%) 연장 · +27.7초(편당 +0.62초) · 겹침쌍 188→188 신규 0 ·
p90 5.51·max 20.80 불변 · p50 2.87→3.02 · 0.4초 미만 14→2줄.**

`12자/초` 는 규격 원문이 egress 차단이라 2차 자료(한 줄 16~18자·1.5초)+실측으로 잡았다고
명시돼 있다. 절대 하한 `0.4초` 는 짧은 감탄사를 살리려 낮게 잡은 값이다(`박수!` 0.52초·3자는
그대로).

⚠ **아직 노드에 안 갔다.** 머지 시점 기준 6대 전부 `d843f0a`. version_watch(시간당 1회)가
`7f7c052` 를 집으면 자동 갱신된다. 게이트가 없으므로 **갱신 즉시 전 채널 자막 타이밍에
적용된다.**

파이프라인이 뽑은 쇼츠 구간이 달라서(LLM 기획이 매번 다르다) 줄 대 줄 대조는 성립하지
않는다. 분포와 동작 흔적으로 본다.

`18줄 · p50 2.07 / p90 3.91 / max 4.35s · 겹침쌍 1 · 저확신 1`

**하한이 실제로 걸렸다.** 여러 줄이 `글자수 / 12` 또는 절대 하한 `0.40` 에 **정확히** 앉아
있다 — 우연으로 나올 수 없는 값이다:

| 줄 | 글자 | 실제 | 필요(=max(0.4, 자/12)) |
|---|---|---|---|
| `우와` | 2 | **0.40** | 0.40 |
| `네!` | 2 | **0.40** | 0.40 |
| `와 감사합니다.` | 8 | 0.70 | 0.67 |
| `여러분. 엄지은!` | 9 | **0.75** | 0.75 |
| `황지윤! 감사합니다.` | 11 | **0.92** | 0.92 |

**감탄사는 안 늘어났다** — `우와`·`네!` 가 절대 하한 0.40 에 머문다. 하한을 크게 잡았으면
장면이 지나간 뒤에도 자막이 남았을 자리다.

**겹침 제약이 지켜진 증거가 데이터에 있다.** 15번 `오늘 센터로 꼭…`(36자·필요 3.00s)은
실제 1.81s 로 **미달인데도 연장되지 않았다.** 다음 줄(16번)이 56.12 에 시작해 15번 끝
56.75 보다 앞서 있다 — 즉 **이미 겹친 쌍**이고, 코드의 `seg.end_sec > next_start` skip
브랜치를 정확히 탄 것이다. 겹침쌍 1건은 E14 가 만든 것이 아니라 원래 있던 것이다.

### ⚠ 사각지대 1건 — 두 규칙 사이에 낀 줄

```
 6   28.21~ 28.50 (0.29s · 9자 · 31자/초) 홍지윤, 홍지윤.
 7   28.50~ 32.41 (3.91s)                 홍지윤 언니 센터 하면 여러분들께서 가자라고 외쳐주시면 됩니다.
```

31자/초는 못 읽는다. 그런데 **어느 규칙도 이 줄을 구하지 못한다**:

- **연장 불가** — 7번이 `28.50` 에 **틈 없이** 시작한다(gap = 0). `min(want_end, next_start)`
  가 곧 현재 end 라 한 발짝도 못 늘린다. E14 는 이걸 `[SubtitleFloor/미달] … 다음 줄
  시작에 막힘` 으로 **로그에 남긴다** — 설계대로 동작한 것이고, 조용히 넘어가지 않았다.
- **병합 불가** — `gap(0) <= max_gap_sec(0.25)` 은 통과하는데, 합치면 45자로
  `effective_max_chars` 40 을 넘는다. 6번이 마침표로 끝나 문장 완결이라 1.3배 완화도
  안 걸린다.

**연장은 옆줄이 막고, 병합은 글자 수가 막는다.** E14 의 결함이 아니라 E14 가 닿지 못하는
자리다. 되돌릴 이유는 아니고, 후속으로 다룰 값어치가 있다(예: 하한 미달이면서 gap=0 인
쌍에 한해 병합 한도를 완화, 또는 두 줄로 나눠 표시).

**판정: E14 는 의도대로 동작한다. 되돌리지 않는다.**

### 원래 필요했던 것 → 발주서 `e14-subtitle-min-display.md`

시간 하한이 아니라 **읽기 속도 하한**이다. 10번은 0.72초로 0.6 하한을 넘기지만 25자/초라
못 읽는다(한국어 자막 관례는 대략 12~14자/초). 다음 cue 시작을 침범하지 않는 선에서
`end_sec` 를 글자수 기준 최소 노출 시간까지 늘려야 한다.

### 저확신 표시는 제 몫을 했다

저확신 3줄(8·9·11번)이 **전부 그 노래 구간**이다. 편집실 ◆ 배지가 검수자를 정확히 그리로
보낸다 — P2-b 가 의도한 그대로다. 다만 10번(타임코드만 깨지고 logprob 은 정상)은 못 잡는다.
logprob 은 '잘 들었나'이지 '타임코드가 맞나'가 아니다.

**곁가지 관찰(표본 1)**: 가왕쇼 첫 cue 가 keyterms off 에서 `제1대 현역가왕 전유진!`,
on 에서 `제일 대 현역가왕 전유진!` 으로 **나빠졌다**. `현역가왕` 을 키텀으로 준 것이
앞 낱말 표기에 영향을 준 것으로 보인다. 표본 하나라 단정하지 않는다.

## 결론

E13 은 발주한 두 가지를 실제로 고쳤다 — **표기는 5/5 로 닫혔고**(keyterms 와 사전이
각각 제 몫을 했다), 판정기는 정상 한국어를 오탐하지 않는다. 속도(9~12배)·요금
($0.27/시간)·이벤트 누출 0·싱크 일치는 두 편에서 일관된다.

**다섯 항목이 다 닫혔고, 그 과정에서 나온 ⑥ 도 닫혔다.**

| # | 결론 |
|---|---|
| ① 표기 | 5/5 — keyterms·사전·수사 규칙이 각각 제 몫 |
| ② 언어 이탈 | 오탐 0(26건 전량). `謝 謝` 미재현이라 **차단 자체는 실증 안 됨** |
| ③ 요금 | $0.27/오디오시간, 두 편 일치 |
| ④ 회귀 0 | E11·E13 회귀 0(코드 증명) · E14 의도적 변경(수치) · TTS 폭발 반경 0 |
| ⑤ cue 분포 | 최종 자막 p50 2.04s — 전사 단계 수치로 판정하면 안 된다는 것이 확인됐다 |
| ⑥ 최소 노출 | E14 `04a3d60` 로 해결. 76/639줄 연장, 겹침 신규 0 |

**하나만 열려 있다 — ② 의 '차단 실증'.** 버린 줄 0·오탐 0 은 확인됐지만, E13 을 발주하게
만든 `謝 謝` 가 재측정에 재현되지 않아 "판정기가 실제로 이탈을 잡는다"는 것을 실측으로
보이지 못했다. 엔진 단위 테스트(`tests/test_e13_transcribe_polish.py`)가 지키고 있고,
운영에서 이탈이 나오면 그때 로그로 확인된다. **추가로 할 일은 없다** — 나올 때까지
기다리는 것이 유일한 방법이고, 안 나오면 그게 좋은 것이다.

어느 것도 "일레븐랩스가 나쁘다"는 근거가 아니다. 오히려 가왕쇼에서는 whisper 쪽이
38.54초 cue 를 내고 우승자 이름을 뭉갰다.

## 권고

### 실제 적용 (2026-08-23)

`ops_config.channel_transcribe = on`. 첫 전환 채널은 **HANIPJUMAK(한 입 주막 · 가왕쇼)** —
`channel_design_overrides.design.transcribe_backend = 'elevenlabs'`. 배경음악 구간에서 내장
whisper 가 38.54초 cue 를 내고 우승자 이름을 뭉개는 것이 이 채널 소스에서 실측됐다.

주의 둘:

- **다음 생성부터 적용된다.** 전사는 생성 초반 단계라 편집실 재렌더(from_step=resources|render)
  에는 반영되지 않는다 — 0072 가 이 키를 편집실이 아니라 채널에 둔 이유가 그것이다.
- 채널 오버라이드는 **통째 교체**(`effective_design`)라 기존 레이아웃 키 13개를 그대로 두고
  키 하나만 더했다. 어댑터가 이 design 으로 `--transcribe-backend elevenlabs` 를 포함한
  13쌍 플래그를 예외 없이 만드는 것까지 확인했다.

첫 편 완성본의 **자막 줄 길이**는 확인했다(⑤·⑥ 참조) — merge 는 제 몫을 했고, 거기서
나온 최소 노출 결함은 E14 로 닫혔다.

---

`channel_transcribe = on` 은 **선택칸을 화면에 띄울 뿐** 어느 채널도 바꾸지 않는다 —
채널 템플릿의 `transcribe_backend` 는 손대기 전까지 `default` 다. 그래서 게이트 자체는
켜도 안전하고, 실제 전환은 **배경음악이 많은 채널 한 곳부터** 한다. whisper 손실이
제일 큰 곳이라 이득이 가장 크고, cue 분포 우려도 그 채널에서 제일 먼저 드러난다.
첫 편 완성본을 보고 자막 줄 길이가 실제로 읽을 만한지 확인한 뒤 넓힌다.

## 재현

```
ssh <노드> 'export PATH=/opt/homebrew/bin:/usr/local/bin:$PATH;
  set -a; . /opt/ves/secrets/ves.env 2>/dev/null; . /etc/ves/node.env 2>/dev/null; set +a;
  cd /opt/ves/engines/ai-video && .venv/bin/python -m scripts.e11_transcribe_ab \
    --video /opt/ves/cache/sources/<sha> --json-out /tmp/e13_ab.json \
    --keyterm <작품명> --keyterm <인물명> ...'
```

`--keyterms-mode` 기본은 `both`(세 판)이고 `--keyterm` 이 하나 이상 필요하다 — 파이프라인은
리서치 결과(작품명·인물명)를 자동으로 넣지만 수동 실행에는 없다.

- 커리어데이 EP8 `d63739ef924aa0bee005c0f1af571cf7f90fc640a06cf32bb496cc6917fc7c32` (611초)
- 가왕쇼 EP1 `e5567c94c6e62503fd2d3ad3f7ed16f66d840e48ed268cf31deb02f6dbeff3c2` (47.1분)

`ELEVENLABS_API_KEY` 는 `/opt/ves/secrets/ves.env` 에 있다(레포 `.env` 아님). 비대화형
SSH 는 PATH 에 homebrew 가 없어 ffmpeg 를 못 찾으므로 위 `export` 가 필요하다. 47분 소스는
세 판이 20분 넘게 걸리니 `nohup … &` 로 떼어 놓는다 — 파이썬이 stdout 을 블록 버퍼링하므로
로그가 한동안 비어 보이는 것은 정상이다.

## E13 실측 중 확인된 것 (엔진 처리 완료)

- `ffmpeg_utils.py` — 미검출 메시지가 실행 중인 OS 기준으로 바뀌었다(종전 윈도우 안내).

  whisper 는 거의 안 찍어 같은 규칙이 한쪽에서만 발동한다. 백엔드 선택이 채널 단위라
  규칙은 그대로 두기로 했다.
