# E13 — Scribe 전사 다듬기: 표기 보존 · 언어 이탈 차단 (ai-video 엔진 발주서)

ai-video(rht-22/ai-video) 엔진 세션용 작업 프롬프트. E11(`--transcribe-backend`)의
**후속**이다 — 기능은 이미 머지돼 전 노드가 `e99cf6a` 를 돌고 있고, 실측 결과 게이트를
막는 것 두 가지가 남았다. 이 발주서가 그 둘이다.

실측 근거: `docs/prompts/e11-transcribe-backend-report.md`(소스 2편, 2026-08-22).
요약하면 — **Scribe 는 빠르고(9~25배) 싸고($0.22/오디오시간) 싱크가 맞고 오디오 이벤트
누출이 0건이다. 배경음악 구간에서는 정확도도 내장 Whisper 보다 낫다.** 막는 건 실력이
아니라 다듬기다.

`ops_config.channel_transcribe` 게이트는 이 둘이 닫힐 때까지 `off` 로 둔다.

## ⚠ 배포 특성 — 회귀 0 이 안전장치다

ai-video 는 `deployments.auto_update=true` 이고 핀이 없다. **main 에 머지하면 version_watch
(시간당 1회)가 새 sha 를 보고 맥미니 6대가 다음 claim 경계에서 자동으로 갱신한다.**

이번 작업은 **전사 텍스트를 고쳐 쓰는 일**이라 종전보다 위험하다. 손대는 범위를
`--transcribe-backend elevenlabs` 경로 안으로 못 박아라. **미지정·`default` 실행은 한
글자도 달라지면 안 된다** — 지금 돌고 있는 모든 작업이 그 경로다. `app/modules/speech.py`
와 `merge_subtitle_segments` 는 건드리지 마라.

## E13-0. 먼저 확인할 것 (구현 전 조사)

**cue 분할이 두 백엔드에서 왜 갈리는지 원인을 확정해라.** 실측에서 방향이 뒤집혔다:

| 소스 | Whisper cue | Scribe cue |
|---|---|---|
| 커리어데이 EP8 (대사, 10.2분) | 206 | 180 |
| 가왕쇼 EP1 (배경음악, 47.1분) | 898 | **1468** |

`stt_elevenlabs.words_to_segments` 의 경계 규칙(0.5s gap · 44자 · 6.0s)은 이미
`merge_subtitle_segments` 와 같은 값으로 맞춰 놨는데도 결과가 갈린다.

**유력한 용의자는 `_SENTENCE_END`(`[.!?…]$` 에서 flush)다.** Scribe 는 한국어에 문장부호를
찍어 주고 Whisper 는 거의 안 찍는다(실측 diff 30건 중 9건이 문장부호만의 차이). 그러면
같은 규칙이 Scribe 에서만 발동해 잘게 쪼개진다 — 가왕쇼의 1468 이 그 모습이다. 확인해서
보고해라.

**단, 이건 이번 발주의 수정 대상이 아니다.** 한쪽이 일관되게 낫지 않고(가왕쇼에서는
Whisper 가 24.7초짜리 cue 를 냈다), 백엔드 선택은 어차피 **채널 단위**라 채널마다 자막
리듬이 다른 건 설계상 허용된다. 원인만 알고 넘어가라 — 고칠지는 그 다음 판단이다.

## E13-1. P1 — 고유명사·표기 보존 (중)

### 증상

Scribe 가 영문 약어와 숫자를 한글로 풀어쓴다. 커리어데이 EP8 실측:

```
SK텔레콤  → 에스케이텔레콤      NC소프트 → 엔씨소프트
CTO       → 씨티오              IT업계   → 아이티 업계
30년      → 삼십년
```

화면에 `에스케이텔레콤`, `씨티오`, `삼십년` 이 뜨면 자막 품질이 떨어진다. 내장 Whisper
는 이 다섯 건을 모두 원표기로 받았다.

### 왜 Whisper 는 되고 Scribe 는 안 되는가 — 이미 답이 코드에 있다

`speech.py` 의 `_build_whisper_prompt` 가 **리서치 결과(인물명·작품명)를 `initial_prompt`
에 주입해** 고유명사 인식을 강화한다. Scribe 의 대응물은 `keyterms` 이고,
`stt_elevenlabs.py` 에 **이미 구현돼 있는데 꺼져 있다**:

```python
EL_STT_KEYTERMS_ENABLED = os.environ.get("ELEVENLABS_STT_KEYTERMS", "") ... # 기본 off
# 주석: 요율이 오르고(+$0.05/오디오시간) 폼 직렬화 형태를 실키로 확인하지 못했다
```

즉 **두 백엔드가 지금 비대칭 조건으로 붙고 있다** — 한쪽만 고유명사 힌트를 받는다.

### P1-a. keyterms 를 실키로 검증하고 기본 on (이번 발주의 본체)

- 실제 키로 한 번 쏴서 `keyterms` **폼 직렬화 형태를 확정해라**(지금은 JSON 배열
  문자열로 보내고 있는데 미검증이다). 서버가 무시하고 있었다면 지금까지의 실측이
  전부 keyterms 없이 나온 것이다.
- 검증되면 `elevenlabs` 경로에서 **기본 on**. Whisper 가 `initial_prompt` 를 늘 받는
  것과 대칭이어야 비교가 공정하다.
- 요율: $0.22 → **$0.27/오디오시간**. 47분 편당 $0.17 → $0.21. Whisper 대비 이득
  (25배 속도)에 비하면 무시할 수준이다. 그래도 `usage_summary` 의 단가 상수가
  keyterms 사용 여부에 따라 갈리게 해서 정산이 틀리지 않게 해라.
- keyterms 가 실제로 `SK텔레콤`·`NC소프트` 를 살리는지 **재측정으로 확인**해라
  (E13-3). 살아나면 P1-b 는 범위가 크게 줄어든다.

### P1-b. keyterms 로 안 잡히는 나머지 (조건부)

`CTO`·`IT`·`30년` 은 리서치 결과에 안 들어가는 일반 어휘라 keyterms 로 못 잡는다.
P1-a 재측정 뒤에도 남으면 그때 처리한다.

- **먼저 API 에 표기 옵션이 있는지 확인해라.** Scribe 쪽에 숫자·약어 표기를 정하는
  파라미터가 있으면 손으로 짜는 것보다 그게 낫다. 없으면 아래로 간다.
- 후처리를 짠다면 **좁게**: (1) 한글 음차 → 원표기 사전을 **완전 토큰 일치**로만
  적용(부분 문자열 치환 금지 — `아이티` 가 들어간 멀쩡한 단어를 깨뜨린다),
  (2) `삼십년` 류는 `한글수사 + 단위` 패턴에 한해 아라비아 숫자로.
- 사전은 코드에 박지 말고 **데이터로** 두고 근거를 남겨라. 이건 전사 결과를 사람이
  안 보는 사이에 고쳐 쓰는 일이라, 무엇을 왜 바꿨는지 로그에 남아야 한다.
- ⚠ **`elevenlabs` 경로 전용이다.** Whisper 결과에 같은 후처리를 먹이면 회귀 0 이
  깨진다.

## E13-2. P2 — 저확신·언어 이탈 줄 처리 (중)

### 증상

가왕쇼 EP1(배경음악)에서 저확신 3건이 나왔고 **그중 하나가 중국어**다:

```
[Scribe-확신도낮음] 2175.6~2177.6s logprob=-1.17 '謝 謝 .'          ← 언어 이탈
[Scribe-확신도낮음] 2581.5~2582.7s logprob=-1.17 '아저씨 이때 좋아요.'  ← 멀쩡한 한국어
[Scribe-확신도낮음]  837.9~ 839.4s logprob=-0.91 '마음처럼.'          ← 멀쩡한 한국어
```

한국어 편에 `謝 謝` 가 자막으로 박히면 안 된다. 지금 `_LOW_CONFIDENCE_LOGPROB = -0.60`
이 **로그만 찍고 결과는 안 바꾼다**(주석에 그렇게 적혀 있다).

### ⚠ logprob 임계로 줄을 버리면 안 된다

위 3건 중 2건은 멀쩡한 한국어다. 임계로 잘라내면 실제 대사가 사라진다. **두 층으로
나눠라.**

### P2-a. 언어 이탈 차단 (좁고 확실 — 이번 발주의 본체)

`language_code=kor` 로 요청한 응답의 cue 에서 **한글·라틴·숫자·문장부호 밖 문자**
(한자·가나·키릴 등)가 지배적이면 그 cue 를 버린다.

- `謝 謝` 를 정확히 잡고 정상 한국어에는 오탐이 없다 — logprob 과 무관하게 판정된다.
- "지배적"의 기준(예: 해당 문자가 cue 텍스트의 절반 이상)은 네가 정하고 근거를 써라.
- ⚠ 한국어 자막에 한자가 정당하게 들어가는 편이 있을 수 있다. 버릴 때 **로그에 남겨라**
  — 조용히 사라지면 아무도 못 잡는다.
- 요청 언어를 그대로 쓰지 말고 응답의 `language_code` 도 같이 봐라(둘이 다르면 그
  자체가 신호다).

### P2-b. 저확신 줄은 버리지 말고 **표시**해라

- 저확신 cue 를 `subtitle_segments.json` 에 표시(예: 줄별 플래그 하나)하고 결과 텍스트는
  그대로 둔다. 편집실이 이미 자막 검수 화면이니 **거기서 사람이 보는 게 맞다**.
- 스키마를 늘리면 **downstream 이 모르는 필드에 안 깨지는지** 확인해라
  (`edit_overrides` · `build_ass` · 편집실 자막 탭). 깨지면 이번엔 `run_log` 요약까지만
  하고 스키마는 건드리지 마라 — 그쪽은 오케스트레이터 협의가 필요하다.
- 대시보드에 띄우는 건 **오케스트레이터 몫이다(별건)**. 지금 `usage_summary()` 의
  `low_confidence_lines` 는 `pipeline.py:2268` 에서 run_log 로만 들어가고 ves 쪽은
  존재를 모른다. 엔진은 데이터를 내놓는 데까지만 하면 된다.

## E13-3. 실측 검증 (필수)

**같은 소스 2편으로 다시 재라** — 이 발주의 전제가 그 두 편에서 나왔다.

- 커리어데이 EP8 (대사 중심, 10.2분) — P1 이 여기서 나왔다
- 가왕쇼 EP1 sha `e5567c94…` (배경음악, 47.1분) — P2 가 여기서 나왔다

도구는 이미 있다: `scripts/e11_transcribe_ab.py`. 재현 명령은 실측 보고서 끝에 있다.

1. **표기 5건이 살았는가** — `SK텔레콤`·`NC소프트`·`CTO`·`IT업계`·`30년`.
   keyterms 만으로 몇 건이 살고 몇 건이 남았는지 **건별로** 적어라.
2. **`謝 謝` 가 사라졌는가, 그리고 멀쩡한 한국어를 안 버렸는가.** 버린 줄 전량을
   목록으로 내라 — 오탐 0건이 통과 조건이다.
3. **요금 변화** — keyterms on 기준 `audio_duration_secs` × 단가. 종전 $0.22/시간
   대비 실제로 얼마가 됐는지.
4. **회귀 0** — `--transcribe-backend` 없는 실행과 `default` 명시 실행이 종전과 완전히
   같은지. E11 에서 못 잰 항목이다: 같은 소스로 작업 두 건을 돌려 `--diff JOB_A JOB_B`
   로 **완성본을 비교해서** 재라. A/B 스크립트로는 안 된다(전사 단계만 돌린다).
5. **cue 수·길이 분포** — E13-0 조사 결과와 함께. 이번 변경이 cue 분할을 의도치 않게
   흔들지 않았는지 확인하는 대조군이다.

## 곁다리 2건 (E11 실측 중 발견, 같은 세션에서 처리)

- `app/modules/ffmpeg_utils.py:163` — ffmpeg 미검출 메시지가 **윈도우 설치법**을 안내한다.
  전 노드가 macOS 다. 운영 영향은 없지만(워커가 PATH 를 주입한다) 수동 실행 때마다 걸린다.
- `app/modules/tts.py:278` — `EL_VOICE_PRESETS.get(voice, EL_VOICE_PRESETS[DEFAULT_VOICE])`.
  모르는 **라벨**이 조용히 기본 목소리로 떨어진다. E12 가 `elevenlabs:` 접두사 경로를
  고치는데 라벨 경로는 여전히 fail-silent 다 — 같은 규율로 즉시 실패해야 한다.
